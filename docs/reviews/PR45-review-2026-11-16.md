- **Reviewed source:** supplied PR #45 / M2.1 snapshot (`baa2c0f` in the supplied review materials)

## Executive assessment

This is a serious market-data collector foundation, not an order-entry engine or an all-purpose trading bot. Its strongest work is the deterministic collector core, explicit numeric model, SBE compatibility discipline, journal integrity/failure behavior, and a substantial mock-exchange test/evidence harness. Its weakest areas are recovery scope isolation, transport-observation provenance, full-universe live proof, and the gap between a large evidence/documentation surface and locally reproducible Rust assurance.

The package makes one bounded correctness correction: exhausting one instrument's stale-probe budget now records an instrument continuity incident and requests another instrument-scoped refresh instead of directly requesting a source reconnect from that branch. The 3,000-instrument regression test is updated to pin the intended behavior. This does **not** complete the recovery redesign: `PendingRecovery` remains source-keyed, carries a `reconnect` boolean, and merges that boolean with `pending.reconnect |= reconnect`. Separate instrument/source queues and exact per-instrument generation fences remain necessary.

ADR-0002 is accepted as the design contract for transport observations and journal v2. The current source still writes journal v1 and does not persist native WebSocket control observations. S1a/S1b are specified, not implemented in this package. The protected data-only `read_records()` accounting contract is explicitly preserved.

## Findings and disposition

### P1 — instrument quietness must not trigger source recovery

The supplied review pin reproduced an active-source recovery request with `reconnect = true` for quiet instrument `Q2999`, while the other 2,999 instruments continued receiving market events. The stale-probe budget branch previously queued both a reconnect request and a reseat. It now queues only a symbol-scoped refresh from that branch. The existing regression test continues to require the quiet symbol to be the only target and the active-source request to remain non-reconnect.

**Disposition:** narrow code correction included; Rust test execution remains blocked. This is not a claim that all recovery actions are now independently scoped. `PendingRecovery` remains keyed by `SourceId`, and its reconnect flag is OR-merged. M3.1–M3.3 must replace this transitional representation with typed actions/causes, independent instrument/source queues, and per-instrument generation/fence acknowledgements.

### P1 — the journal cannot prove transport facts currently observed by sessions

The current `ws::next_payload()` automatically answers native Ping and returns `Idle`, losing the inbound Ping payload before the adapter/worker can persist it. Kalshi native Pong is mapped to `FrameKind::Binary`, which is not its wire frame class. Polymarket's application-text `PING`/`PONG` heartbeat is distinct from native WebSocket Ping/Pong, and the native Pong is not an application heartbeat acknowledgement. `SessionSignal` and the heartbeat mechanism are not persisted in v1.

**Disposition:** ADR-0002 accepted in this package. It defines `receive_seq`, `control_seq`, and `observation_seq` per `(SourceId, connection_epoch)`, typed direction/classification/signal/mechanism, a data-only `read_records()` compatibility API, and a complete `read_observations()` API. S1a (transport preservation) and S1b (journal v2) remain unimplemented and are explicit merge blockers for the audit objective.

### P1 — recovery acknowledgement scope remains too broad

Current recovery acknowledgement is source/generation-oriented, while several instruments can have independent recovery generations. A source-level batch acknowledgement can affect unrelated instrument requests unless exact target identities and generations are carried through the control path.

**Disposition:** not silently changed in this patch. Implement M3.2/M3.3 after S1a/S1b, with exact target identities, stale-generation rejection, connection-epoch checks, and tests proving old acknowledgements cannot mutate unrelated instruments.

### P2 — full-universe claims need to remain evidence-classed

The repository records 548,942 unique discovered outcome tokens in a discovery run and a separate failed capture with 385,604 expected symbols. The project also records a 100k-symbol synthetic test envelope. These are not the same metric or evidence class. Discovery does not prove simultaneous subscription, snapshot anchoring, or sustained live collection of the entire universe.

**Disposition:** README wording now distinguishes those counts. Keep full-universe success/soak claims gated on per-symbol acknowledgements, snapshots, reconciled event accounting, journal verification, and retained live artifacts. Add host/network/CPU/memory telemetry before attributing the historical 756 connection errors and large failover-snapshot burst to one cause.

### P2 — repository hygiene policy was violated by tracked auxiliary files

The checked-in `git-policy.json` explicitly forbids `.vscode/` and `repomix.config.json`, but both were tracked. A generated `scripts/__pycache__/` also existed locally.

**Disposition:** removed the two tracked forbidden paths and the generated Python cache. Build, test, deployment, schema, raw measurements, and assurance scripts were retained.

### P2 — broken documentation reference and ambiguous universe count

`measurements/README.md` linked to a missing `docs/final-verification-2026-10-25.md`; it now points to `docs/verification.md`. README wording no longer treats the 548,942-token planning/discovery count and 385,604-symbol failed-capture expected set as interchangeable.

**Disposition:** corrected and checked all repository Markdown relative links.

## Accepted journal contract (ADR-0002)

Three per-source/per-epoch sequence domains preserve both book ordering and the interleaving of control/data observations:

- `receive_seq`: every inbound Text/Binary WebSocket data frame, including application-text heartbeat messages; remains the collector/book fence.
- `control_seq`: native inbound/outbound Ping/Pong control frames.
- `observation_seq`: all retained inbound/outbound observations, preserving worker observation order.

The protocol facts are adapter-assigned, not inferred from bytes during replay. Polymarket application-text heartbeat and Kalshi native-control heartbeat are explicitly distinguished. The protected `journal_accounts_for_every_delivered_payload` test remains data-only; controls are exposed only via `read_observations()` after S1a/S1b. Keep the v1 golden fixture unchanged and preserve v1 readers.

## Open-source reference strategy

The Voluntas challenge repository is a small SBE-oriented starter template, not a complete market-data platform. Keep its FIX SBE schema/wire compatibility as a hard boundary. The WallStreetPete directory is useful as a discovery index for venue clients, datasets, backtesting systems, and cross-venue API patterns; it is not a quality certification. Reuse narrowly: compare official/canonical Kalshi and Polymarket client behavior for protocol fixtures, study multi-venue abstractions for adapter ergonomics, and keep analytical/backtesting systems downstream from the collector. Do not graft order-execution or strategy-bot subsystems into this public market-data collector merely to increase feature count.

There is no defensible objective metric for “best project in the world.” The credible target is a project that passes every stated contract, proves full-universe claims with reproducible evidence, preserves venue protocol facts, and demonstrates bounded recovery blast radius under failure.
